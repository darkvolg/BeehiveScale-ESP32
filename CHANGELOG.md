## [4.2.9] — 2026-05-04

### Изменено — двойное подтверждение тарирования
- **`TARE_COUNT` 1 → 2** (`BeehiveScale.ino`). Случайное нажатие при пробуждении LCD из режима ожидания больше не запускает тарирование. Защита от потери данных в улье при случайном касании.
- **Первое нажатие** D3 → показывает запрос на LCD: «Tara? Nazhmite esche 1 raz/3sek».
- **Второе нажатие** в течение 3 секунд → выполняется тарирование.
- **Таймаут 3 сек** без второго нажатия → показывает «Tara: otmena» и возвращается к обычному экрану.
- Калибровка (D3 удержание 5 сек) — без изменений.

## [4.2.8] — 2026-05-04

### Исправлено — авто-тарирование при включении (регрессия v4.2.6)
- При включении весов GPIO0 (D3, главная кнопка) — boot-strap пин ESP8266, в момент инициализации даёт переходные процессы. FALLING-прерывание ловило их как «нажатие», и в v4.2.6 (после уменьшения `TARE_COUNT` 4→1) это автоматически запускало тарирование с грузом на платформе.
- **Фикс 1:** в конце `setup()` сбрасываем ISR-флаги обоих кнопок (`btnMain.irqFell`, `btnMenu.irqFell`).
- **Фикс 2:** в `handle_buttons()` добавлен boot grace period — первые 2 секунды после старта кнопки игнорируются, ISR-флаги периодически чистятся.

## [4.2.7] — 2026-05-04

### Изменено — порог LONG_PRESS
- **`LONG_PRESS_MS` 2000мс → 5000мс** в `Button.cpp`. Калибровка (D3 hold) и «домой» из меню (D4 hold) теперь требуют удержания 5 секунд вместо 2. Защита от случайного запуска опасной калибровки. Тарирование (D3 одно короткое нажатие) — без изменений.

## [4.2.6] — 2026-05-04

### Изменено — UX кнопки тарирования
- **`TARE_COUNT` 4 → 1** (`BeehiveScale.ino`). Раньше для тарирования требовалось 4 коротких нажатия за 5 секунд (без визуальной обратной связи на LCD), что воспринималось пользователем как «работает через раз». Теперь — **одно короткое нажатие = тарирование**, как на стандартных весах.
- Долгое нажатие главной кнопки = по-прежнему калибровка (защита от случайного запуска опасной операции).
- Двойное нажатие меню-кнопки = по-прежнему отмена тары (undo_tare).

## [4.2.5] — 2026-05-04

### Изменено — точность отображения LCD
- **Главный экран веса:** `%6.2f kg` → `%6.1f kg` (сотые → десятые). Для пасеки точность 100г более чем достаточно (прирост 0.5–3 кг/день видно отлично), убирает «дрожание» младшей цифры.
- **Экран разницы (D:):** аналогично `%6.2f` → `%6.1f` для текущей и предыдущей разницы.
- В CSV-логах и в Telegram точность сохранена на уровне `%.2f` — для аналитики и графиков.
- В экране ручной подстройки калибровочного фактора (CF) точность веса оставлена `%6.2f` — там нужно видеть мелкие изменения для точной настройки.

### Активировано LEGACY_HX711_PINS
- В этой сборке HX711 на пинах **D0 (GPIO16) / TX (GPIO1)** — соответствует физической распиновке весов Геннадия. Serial Monitor не работает (TX занят SCK).

## [4.2.4] — 2026-05-04

### Изменено — UX скорости отклика и стабильности нуля
- **Интервал чтения HX711:** 2500мс → **1500мс** (`SCALE_READ_INTERVAL_MS` в `BeehiveScale.ino`). Время отклика на полное изменение веса упало с ~25 сек до ~10 сек.
- **EMA α по умолчанию:** 0.2 → **0.3** (`Memory.cpp`). Более быстрый отклик при сохранении фильтрации импульсов от пчёл (<1 сек длительности).
- **Auto-zero deadband:** 0.001 кг (1 г) → **0.05 кг (50 г)** (`ZERO_DEADBAND_KG` в `BeehiveScale.ino`). Убирает дрожание показаний возле нуля (-0.01 / +0.02 → теперь стабильно 0.000).

### Улучшено — Веб-интерфейс
- Поле «EMA сглаживание α» переименовано в **«Скорость отклика весов»** с понятным описанием: 0.1 = медленно (улей), 0.3 = средне (рекомендуется), 0.6 = быстро (тесты).
- Подсказка в блоке «Описание» теперь объясняет рекомендуемые значения для разных режимов работы.

### Техническое
- Существующие EEPROM-настройки сохраняются: если у пользователя уже стоит α=0.2, она не перезапишется. Чтобы получить новый дефолт 0.3 — задать вручную через веб-интерфейс или через POST `/api/settings`.

## [4.2.3] — 2026-05-03

### Добавлено
- Build-флаг `LEGACY_HX711_PINS` в `BeehiveScale.ino` — позволяет временно вернуть HX711 на старые пины D0 (DT) / TX (SCK) для диагностики. По умолчанию выключен. При активации автоматически делает `Serial.end()` перед `scale_init()` чтобы UART TX не конфликтовал с HX711 SCK.

### Зафиксировано (диагностика 2026-05-03)
- HX711 модуль конкретного экземпляра весов вышел из строя. Симптомы: тарирование показывает близкие к 0 значения (-0.7 кг шум), но **нагрузка не считывается** (90 кг → реакции нет). Воспроизведено на двух разных тензодатчиках и двух распиновках (D5/D6 и D0/TX). Решение — замена HX711 модуля. Подтверждается мультиметром: между E+ и E− должно быть ~3.3 В (excitation), при смерти HX711 = 0 В.

## [4.2.1] — 2026-05-03

### Исправлено — корневая причина нестабильного веса
- **HX711 перенесён с GPIO16/GPIO1 на GPIO14/GPIO12 (D5/D6)** — стандартные пины ESP8266 для HX711, как в эталонной прошивке Bee_Lite_D1 v1.1. Прежняя распиновка не имела внутреннего pull-up на DOUT (GPIO16) и использовала UART TX как SCK (GPIO1), что давало плавающий вес и ложные срабатывания spike-фильтра / watchdog.
- Убран костыль `Serial.end()` перед `scale_init()` — больше не нужен, UART TX свободен.
- Удалён anti-stuck блок из `scale_read_weight()` (3 лишних raw чтения после `get_units`) — удваивал окно ловли наводок и не давал реальной защиты.
- Удалён дублирующий вызов `set_scale()`/`set_offset()` после `wifi_init()` — это были no-op в RAM, не имели смысла.
- Интервал чтения веса 800мс → 2500мс — снижает температурный дрейф HX711 и даёт WebServer окно на обработку запросов.

### Изменено
- Эталонный груз калибровки: верхний предел 5 кг → 50 кг (для калибровки по тяжёлым гирям при больших ульях).

### Удалено
- **SD-карта отключена** (`#define USE_SD_CARD` закомментирован в Logger.h). Логи и бэкапы теперь только в LittleFS (внутренний flash ESP8266). Причина: D5/D6/D7/D8 освобождаются от SPI, чтобы HX711 мог встать на стандартную D5/D6. В полевых условиях LittleFS надёжнее SD (нет окисления контактов слота, выдерживает -40..+85°C, FS с journaling).

### Изменено
- `LOG_INTERVAL_MS`: 1 мин → 5 мин (для пасеки достаточно, снижает износ LittleFS в 5x).

### Hardware
- ⚠ **Требуется перекоммутация HX711:** DT с D0 на D5, SCK с TX на D6. SD-карту физически можно оставить на коннекторе — она просто не будет использоваться.
- ⚠ **При прошивке в Arduino IDE выбрать**: Tools → Flash Size → **4MB (FS:2MB OTA:~512KB)** — для запаса места в LittleFS.
- Admin-пароль и OTA-пароль вынесены в EEPROM (больше не хардкод в исходниках)
- Добавлена CSRF-защита на все POST endpoints
- Санитизация CSV (защита от формула-инъекций в Excel/LibreOffice)
- `_maskSecret` больше не обрезает токены >63 байт, а маскирует середину
- Rate limit на `/api/log` и `/api/data`

### Исправлено
- `start_webserver()` теперь идемпотентный при Wi-Fi reconnect
- Guard на `sleepDur=0` в `loop()`
- `/api/reboot` отдаёт JSON до `ESP.restart()`, а не после
- RTC fallback больше не использует `__DATE__` — берёт последнее время из EEPROM
- Atomic rotate лог-файла на SD (write→verify→remove вместо copy+rename)
- Убран автоматический `LittleFS.format()` при ошибке `begin()`
- Сброс `spikeRejectCnt` при NaN
- Partial queue send: позиция снимается до закрытия файла

### Изменено
- `String` заменён на `char[]` + `snprintf` в горячих путях (Logger, WebServer, RTC)
- `/api/backup/restore` делает один `EEPROM.commit()` вместо 18 подряд (износ flash)
- `yield()` добавлен в BearSSL handshake
- Log rotate: при ошибке ротации лог truncate'ится вместо роста в бесконечность
- `apPassBuf` стал локальной переменной (race fix)

### Удалено
- Dummy-поле `humidity` из API (нет физического датчика)
- Посторонний `сервер.txt` (документация VPN от другого проекта)

## [4.1.0] — 2026-03-09

Baseline версия. Полный функционал:

- HX711 тензодатчик с EMA-сглаживанием и spike-фильтром
- DS18B20 термометр, DS3231 RTC
- LCD 1602 I2C с 7 экранами меню
- SD-карта CSV логирование
- Веб-интерфейс с REST API (Basic Auth `admin/beehive`)
- Telegram уведомления
- ThingSpeak облако
- Deep Sleep через 3 мин неактивности
- EEPROM калибровка с magic bytes
- OTA обновление (пароль `ota_beehive`)
