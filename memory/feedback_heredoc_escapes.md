# Генерация кода через bash heredoc ломает escape-последовательности

При правке `Logger.cpp` (v5.0.69) код генерировался Python-скриптом, переданным в `py -3` через `bash <<'PYEOF'`. Результат в файле:

- `\n` внутри строкового литерала C++ → **реальный перевод строки** → `error: missing terminating " character`
- `'\0'` → **настоящий NUL-байт** в исходнике → `grep` начал считать файл бинарным
- три попытки починить тем же способом (`py -3 -c "..."` в кавычках) провалились — шелл мангалил экранирование на каждом круге

**Why:** цепочка bash → heredoc → Python-строка → C++ литерал даёт четыре уровня экранирования. Даже с `<<'PYEOF'` (без подстановки) обратные слэши внутри Python-литералов интерпретируются не так, как ожидаешь.

**How to apply:**
- Скрипт-патчер длиннее пары строк → записать **файлом** инструментом Write в scratchpad, потом `py -3 путь/скрипт.py`. Один уровень экранирования вместо четырёх.
- Для байтовых правок работать с `open(p,"rb")` и явными байтовыми константами (`b"\x5c\x6e"` вместо `b"\\n"`) — читается однозначно.
- После генерации кода **всегда компилировать**, а не верить, что записалось правильно.
- Простые однострочные `sed -i 's|A|B|'` по-прежнему нормальны — проблема именно в многоуровневой генерации.
