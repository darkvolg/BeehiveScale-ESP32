## MEDIUM (3) — архитектурные, оставлены осознанно

### M1. `wifi_ensure_connected()` — блокирующий reconnect 7 секунд
**Файл**: Connectivity.cpp:141
**Проблема**: `while (WiFi.status() != WL_CONNECTED && millis() - start < 7000UL)` — блокирует loop. LCD, кнопки, веб-сервер не обслуживаются.
**Вердикт**: Оставить — penalty 5 мин после неудачи снижает частоту. Рефакторинг (state machine) рискован.

### M2. `ntp_sync_time()` — блокировка до 15 секунд
**Файл**: Connectivity.cpp:485-487
**Проблема**: `delay(1000)` × до 15 итераций. В setup() приемлемо, в ntp_loop() (раз в час) — заметно.
**Вердикт**: Оставить — раз в час, retry 1-2 мин при неудаче.

### M3. `_handleBackup` — двойной `_buildBackupJson` = heap pressure
**Файл**: WebServerModule.cpp:1889-1891
**Проблема**: Два последовательных DynamicJsonDocument(768) + String. При heap ~16KB это ~6% каждый.
**Вердикт**: Оставить — backup редкая операция, деструкция последовательная.

## MINOR (5) — допустимые компромиссы

### m1. `display_screen_diag()` — 4+ секунд блокировки loop
**Файл**: BeehiveScale.ino:874-944
**Вердикт**: Оставить — ручная диагностика, пользователь ожидает задержку.

### m2. `adjust_calibration()` — бесконечный цикл с 5 мин таймаутом
**Файл**: BeehiveScale.ino:979
**Вердикт**: Оставить — интерактивный процесс, управляется кнопками.

### m3. `log_to_json` — trailing newline = ±1 строка
**Файл**: Logger.cpp:708
**Проблема**: `totalLines` может быть на 1 больше при trailing `\n`. skipLines может пропустить одну запись.
**Вердикт**: Допустимо — ±1 строка из 50 не критично для графика.

### m4. `webserver_stop()` не сбрасывает `webServerStarted`
**Файл**: WebServerModule.cpp:2049
**Вердикт**: Допустимо — вызывается только перед deep sleep → ESP перезагружается.

### m5. `Serial.println` после `Serial.end()`
**Файл**: множественные
**Вердикт**: Оставить — dead code, но полезно при отладке. ~500 байт Flash.
